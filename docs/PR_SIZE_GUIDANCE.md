# Pull Request Size Guidance

Prefer pull requests that make one coherent change and can be understood without reconstructing a long story.

## Before opening a PR

- Split unrelated changes into separate pull requests.
- Keep formatting-only changes separate from behavior changes when practical.
- Explain why the change is needed, not only which files changed.
- Include a small example or screenshot when it makes the result easier to verify.

## When a change is large

Explain why the work cannot reasonably be split, identify the most important files to review first, and call out risky assumptions or follow-up work.

A small PR is not automatically a good PR. Clarity and a coherent purpose matter more than an arbitrary line count.
