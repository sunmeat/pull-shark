# Issue Triage

Use this checklist to keep the issue tracker understandable and actionable.

## Triage steps

1. Confirm the report describes a repository-related problem or proposal.
2. Search for duplicates and link related issues when appropriate.
3. Ask for missing reproduction steps or context before drawing conclusions.
4. Apply an existing label that describes the type or status of the issue.
5. Record a next step, owner, or decision when one is known.
6. Close resolved issues with a short explanation and a link to the change when possible.

## Principles

- Be respectful and assume good intent.
- Do not promise a delivery date without a clear commitment.
- Keep discussions focused on one problem at a time.
- Escalate suspected security vulnerabilities using [the security policy](../SECURITY.md), not a public issue.
