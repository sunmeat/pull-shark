# Security Report Checklist

Use this checklist when preparing a private vulnerability report.

- Identify the affected repository path or workflow.
- Describe the expected behavior and the observed behavior.
- Include minimal, safe reproduction steps.
- Explain the potential impact and who could be affected.
- Include relevant versions and sanitized logs when useful.
- Remove passwords, access tokens, personal data, and other secrets from all attachments.

Do not test against systems or data you do not own or have permission to assess. Keep details of an unpatched vulnerability private while the maintainer investigates it.

See the repository's [Security Policy](../SECURITY.md) for reporting guidance.
