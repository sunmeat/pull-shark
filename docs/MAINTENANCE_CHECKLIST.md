# Repository Maintenance Checklist

Use this checklist during a periodic repository review and before a significant release. Not every item applies to every review.

## Documentation

- [ ] Verify that links point to existing pages and files.
- [ ] Review instructions that depend on GitHub interface or policy changes.
- [ ] Remove contradictory, duplicated, or obsolete guidance.
- [ ] Confirm the repository map and README reflect the current structure.
- [ ] Review the changelog for notable changes that are missing.

## GitHub configuration

- [ ] Review issue forms and pull-request templates.
- [ ] Confirm workflow permissions follow least privilege.
- [ ] Review scheduled workflows and dependency update settings.
- [ ] Check whether repository rules still match the intended contribution process.
- [ ] Confirm CODEOWNERS entries refer to people with appropriate repository access.

## Security and access

- [ ] Check for accidentally committed credentials or private data.
- [ ] Review the security reporting instructions.
- [ ] Review collaborator access when team membership or responsibilities change.
- [ ] Confirm that secrets are not printed in workflow logs.

## Community health

- [ ] Ensure support and contribution routes are current.
- [ ] Review open issues and pull requests for stale or unclear status.
- [ ] Check that community guidance remains respectful and actionable.

## Record the review

Record substantial findings in an issue or pull request. If no changes are needed, a checklist can still serve as evidence of what was reviewed and when. Do not claim a check was completed unless it was actually performed.
