# Release Checklist

Use this checklist before tagging or announcing a repository release.

- [ ] Confirm the intended changes are merged into the default branch.
- [ ] Review open issues and pull requests for anything that should block the release.
- [ ] Verify Markdown lint and other configured GitHub Actions checks pass.
- [ ] Check links and references in the documentation.
- [ ] Update `CHANGELOG.md` with notable changes.
- [ ] Confirm README instructions and repository links are current.
- [ ] Create a GitHub release with a concise summary when a versioned release is needed.
- [ ] After publishing, verify the release page and record follow-up work.
