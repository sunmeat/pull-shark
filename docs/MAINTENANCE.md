# Maintenance Policy

This repository is a small example project for practicing GitHub workflows. Maintenance is best-effort and may depend on available time.

## What to expect

- Clear bug reports and focused pull requests are easier to review.
- Security reports should follow [SECURITY.md](../SECURITY.md).
- Dependency updates should be evaluated for compatibility before merging.
- Issues may be closed when they are duplicates, out of scope, or no longer reproducible, with an explanation where practical.

## Scope

Please open an issue before proposing a large change. An issue is a place to discuss the goal and trade-offs; it does not guarantee that the change will be accepted or delivered by a particular date.
