# Documentation Review Checklist

Use this checklist when reviewing a substantial documentation change. Skip items that do not apply and explain any important limitation.

## Accuracy

- [ ] Instructions reflect the current repository and GitHub behavior.
- [ ] Commands, paths, names, and examples are correct.
- [ ] Assumptions and prerequisites are stated.
- [ ] Claims that may become outdated have an appropriate source or context.

## Structure and clarity

- [ ] The title describes the page's purpose.
- [ ] Headings follow a logical hierarchy.
- [ ] The intended audience can follow the instructions without guessing.
- [ ] Abbreviations and specialized terms are explained when needed.
- [ ] Repeated guidance links to a canonical source instead of drifting into duplicates.

## Links and examples

- [ ] Relative links resolve to tracked files.
- [ ] External links point to relevant, stable destinations.
- [ ] Code and configuration examples are formatted correctly.
- [ ] Example values are clearly distinguished from real credentials or production settings.

## Accessibility

- [ ] Link text is meaningful out of context.
- [ ] Tables are simple enough to scan.
- [ ] Important information is not conveyed by color alone.
- [ ] Images and diagrams have text alternatives when needed.

## Maintenance and security

- [ ] Related pages and the repository map are updated if necessary.
- [ ] No secrets, personal information, or private vulnerability details are included.
- [ ] Any checks that could not be completed are stated in the pull request.

A checklist supports review but does not replace judgment. Reviewers should focus on the risks and reader impact of the specific change.
