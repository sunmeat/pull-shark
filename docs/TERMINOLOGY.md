# Terminology

This glossary defines terms used in Pull Shark documentation.

| Term | Meaning |
| --- | --- |
| Base branch | The branch a pull request proposes to merge changes into, commonly `main`. |
| Branch protection | Rules that restrict how changes can be merged into a branch. |
| Change log | A record of notable changes over time, maintained in `CHANGELOG.md`. |
| Code owner | A person or team listed in `CODEOWNERS` for specified paths. |
| Commit | A recorded snapshot of changes in Git history. |
| Continuous integration (CI) | Automated checks that run in response to repository events or schedules. |
| Issue | A GitHub discussion item used to track a problem, question, or proposal. |
| Maintainer | A person responsible for reviewing and managing the repository. |
| Pull request (PR) | A proposal to merge changes from one branch into another. |
| Review | Evaluation of a proposed change before it is merged. |
| Workflow | An automated GitHub Actions process defined by a workflow file. |
| YAML | A human-readable data format used by GitHub issue forms and workflow configuration. |

## Writing guidance

Prefer the full term on first use when readers may not know the abbreviation. Use terms consistently across the README, contribution guidance, issue forms, and pull-request templates.

If the repository adopts a new recurring technical term, update this glossary when doing so would help contributors understand the project.
