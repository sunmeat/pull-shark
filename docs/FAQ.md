# Frequently Asked Questions

## What is Pull Shark?

Pull Shark is a small practice repository for demonstrating a clear, maintainable GitHub pull-request workflow. Its focus is repository practices and documentation rather than a packaged application.

## How do I propose a change?

Open an issue to discuss a question or improvement, or create a focused branch and pull request for a concrete change. Follow [CONTRIBUTING.md](../CONTRIBUTING.md).

## Why should changes be small?

Small pull requests are easier to understand, review, test, and revert. Separate unrelated changes so reviewers can evaluate each decision independently.

## Where should I report a bug or documentation problem?

Use the matching form under GitHub Issues. Include the affected file, what you expected, and enough context to reproduce or understand the problem.

## How do I report a security vulnerability?

Do not publish sensitive details in a public issue. Follow the private reporting instructions in [SECURITY.md](../SECURITY.md).

## Does every change need a release?

No. This repository is primarily a workflow and documentation example. Record notable repository changes in [CHANGELOG.md](../CHANGELOG.md); create a formal release only when it provides a useful, identifiable milestone.
