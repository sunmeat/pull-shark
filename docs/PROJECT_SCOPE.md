# Project Scope

## Purpose

Pull Shark demonstrates a healthy, understandable GitHub pull-request workflow through repository structure, contributor guidance, issue forms, and maintainable documentation.

## In scope

- Clear README and contribution instructions.
- Community, security, support, and governance policies.
- Practical examples of focused branches and pull requests.
- GitHub issue forms, pull-request templates, and relevant automation.
- Documentation quality, accessibility, and repository maintenance practices.
- Small examples that help contributors understand the workflow.

## Out of scope

Unless the project explicitly adopts a new direction, the repository is not intended to be:

- A production application or hosted service.
- A general-purpose software library or SDK.
- A replacement for GitHub's own documentation or security features.
- A place to store credentials, private data, or real vulnerability reports.
- A demonstration of every possible language, framework, CI provider, or deployment platform.

## How to evaluate proposed changes

A proposed change should improve clarity, safety, maintainability, or the practical learning value of the repository. Prefer a small, concrete example over a large configuration added only to make the repository appear more complex.

If a proposal materially expands the scope, discuss the rationale in an issue or decision record before implementation.

## Keeping scope current

Update this document when the repository's purpose changes. Related changes may require updates to the README, repository map, governance policy, and release policy.
