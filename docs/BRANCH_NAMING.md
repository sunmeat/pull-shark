# Branch Naming

Use short, descriptive branch names that explain the purpose of a change. Prefer lowercase words separated by hyphens.

Recommended prefixes:

- `docs/` for documentation updates
- `fix/` for bug fixes
- `feat/` for new functionality
- `chore/` for maintenance and tooling
- `test/` for test-related work

Examples:

- `docs/update-contributing-guide`
- `fix/broken-readme-link`
- `chore/update-actions`

Avoid spaces and vague names such as `updates`. Keep a branch focused on one logical change and delete it after merging when it is no longer needed.
