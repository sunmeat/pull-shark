# Documentation Style Guide

Write documentation for a reader who is new to the repository.

- Use descriptive headings that communicate the topic of each section.
- Prefer short paragraphs and direct instructions.
- Use fenced code blocks with a language identifier when showing code.
- Use relative links for files within this repository.
- Explain acronyms on first use when they are not widely known.
- Keep examples minimal, correct, and easy to copy.
- Avoid promising behavior that the repository does not implement.
- Update related documentation in the same change when practical.

Run the configured Markdown checks before submitting documentation changes.
