# Accessibility

Pull Shark aims to make its documentation and contribution workflow usable by as many people as possible.

## Our approach

- Use descriptive headings and meaningful link text.
- Prefer plain language and explain repository-specific terms.
- Do not rely on color alone to convey meaning.
- Keep tables simple and provide context before complex examples.
- Use descriptive labels for issue forms and pull-request checklists.
- When adding screenshots or diagrams, provide useful alternative text or a text equivalent.
- Review changes for keyboard usability when they introduce interactive examples or interfaces.

## Reporting an accessibility barrier

Open a documentation improvement issue and identify the affected file, the barrier you encountered, and what would make the content more accessible. Do not include sensitive personal information.

For detailed guidance, see [the accessibility documentation](docs/ACCESSIBILITY.md).

## Scope

This policy applies to repository documentation, issue forms, pull-request templates, and any examples or interfaces added in the future. It does not claim that every external service linked from this repository conforms to an accessibility standard.
