# Contributing

Thanks for helping improve Pull Shark. Small, focused changes are easiest to review and maintain.

## Before opening a pull request

- Check existing documentation to avoid duplicating guidance.
- Keep each change focused on one purpose.
- Use a descriptive branch name such as `docs/update-guide` or `ci/lint-markdown`.
- Write commit messages that explain the change.

## Pull requests

- Explain why the change is needed and what it changes.
- Link related issues when applicable.
- Include screenshots only when they help explain a visual change.
- Confirm that Markdown formatting is valid and automated checks pass.
- Do not include credentials, tokens, or private data.

## Review

Address review feedback before merging. Prefer clarity and correctness over the size of a change.
